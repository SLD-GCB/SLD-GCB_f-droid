# 自建 F-Droid 仓库 · 搭建全过程

把 SLD-GCB 自研的安卓应用做成一个用户可订阅的 F-Droid 仓库，从零到上线的完整记录。
留档用 —— 万一以后要重建、或者要给别人照着做。

- 目标仓库：`SLD-GCB/SLD-GCB_f-droid`
- 用户地址：`https://sld-gcb.github.io/SLD-GCB_f-droid/repo/`
- 搭建日期：2026-10-14

---

## 0. 先搞清楚：为什么要“自建”，而不是上官方商店

F-Droid 官方主仓库（f-droid.org）的门槛和自建仓库完全不是一回事。

| | 官方主仓库 | 自建仓库 |
|---|---|---|
| 谁编译 | F-Droid 的 buildserver 从源码编译 | 你自己 / 自己的 CI |
| 谁签名 | **F-Droid 的密钥**（除非做可复现构建） | **你自己的密钥** |
| 老用户升级 | 签名变了，**必须卸载重装** | 无缝升级 |
| 审核 | 人工 review + CI | 无 |
| 曝光 | 官方商店里能搜到 | 用户得自己知道地址 |

**本项目的关键判断**：应用已经开发完成、不再迭代，而且事先已经在 GitHub Release 上分发过自己签名的 APK。
走官方主仓库会让所有老用户必须卸载重装 —— 为了“曝光”付这个代价不划算。
所以选 **自建仓库**：保留自己的签名，老用户无感。

> 补充：官方主仓库还有一条硬门槛 —— 需要能在 Debian 环境用纯 FLOSS 工具链编译出来。
> 这些项目用的是 AGP 9 / compileSdk 37，以及 `io.github.anilbeesetti:nextlib-media3ext`
> （GPL-3.0，内含预编译 FFmpeg），编译工具链和 F-Droid buildserver 对不齐，迁移成本很高。

### 走过的弯路（留个教训）

一开始试图**自己写一套 workflow**：apt 装 fdroidserver → venv 里 pip 升级 → 下载 APK →
`fdroid update` → 发布。连挂 3 次 CI，最后推翻，改用现成模板。结论：

> **这类“有成熟轮子”的事，先搜现成方案。**

## 1. 选方案：用现成模板

用的是 [AoEiuV020/f-droid-repo](https://github.com/AoEiuV020/f-droid-repo) —— 一个中文的 F-Droid
私有仓库模板，分支结构、脚本、workflow 都写好了。**不用自己写任何 workflow。**

它的设计：

| 分支 | 作用 |
|---|---|
| `main` | 模板本体 + 脚本 + workflow |
| `gh-pages` | 真正的 F-Droid 仓库内容（APK、索引、元数据），GitHub Pages 从这里出 |
| `actions` | **发布入口**，往 `apk/` 放文件就触发发布 |

工作流（`.github/workflows/process-apk.yml`）做的事：

```
apk/ 有变化
  → clone gh-pages 到 fdroid/
  → 处理 apk/ 里的文件（下载 URL，或直接用 APK 文件）
  → 从 Secrets 还原 keystore.p12 + 现场生成 config.yml
  → 用 Docker 跑 fdroid update 生成索引
  → 提交并推回 gh-pages
  → GitHub Pages 自动重新部署
```

**CI 里跑的是 fdroidserver 官方 Docker 镜像，所以本机不需要装 Docker。**

## 2. 关键前提：仓库签名密钥

F-Droid 客户端靠**仓库签名密钥的指纹**来确认“这个仓库没被人篡改”。
所以要先有一把密钥，并把它保管好。

- 类型：PKCS12（`keystore.p12`），RSA 4096
- 别名：`fdroidrepo`
- 生成方式：`keytool -genkeypair`（或 `fdroid init`）
- 指纹（SHA-256）：见仓库 README

**两条铁律：**

1. 私钥**绝不能进 git 仓库**，以 base64 存在 GitHub Actions Secrets 里
2. **务必在仓库之外离线备份。** 丢了，老用户就无法继续从本仓库更新 ——
   Android 不允许换签名升级，他们只能卸载重装；而且指纹会变，所有用户都要重新添加仓库

> Windows 上 `fdroid init` 跑不通（会卡在 Android SDK 检测），所以密钥是用 `keytool` 手工生成的。

## 3. 动手：从零搭起来

以下命令在本地跑。需要：git、keytool（JDK 自带）。

### 3.1 Fork 模板

打开 <https://github.com/AoEiuV020/f-droid-repo> → 右上角 **Fork** → Owner 选自己 → 仓库名自取 → Create fork。

> 注意：模板仓库没开 “template repository”，所以是 Fork，不是 “Use this template”。

### 3.2 建 `gh-pages` 分支

模板的 `script/init-gh-pages.sh` 干的就是这件事，是**纯 git 操作**，不需要 Docker，可以照着手做：

```bash
git clone https://github.com/<你>/<仓库>.git && cd <仓库>

rm -rf fdroid && mkdir fdroid && cd fdroid
git init
git checkout --orphan gh-pages
printf '# F-Droid 仓库页面\n' > README.md
printf '/config.yml\n/keystore.p12\n' > .gitignore
git add . && git commit -m "Initial commit"
git remote add origin https://github.com/<你>/<仓库>.git
git push --force origin gh-pages
```

> `gh-pages` 分支其实**几乎不需要内容** —— 索引、APK、`config.yml` 都是发布时生成的。
> 它的 `.gitignore` 特意忽略了 `config.yml` 和 `keystore.p12`，这两个每次发布时从 Secrets 现场生成。

### 3.3 把 `fdroid` 子模块指向自己的仓库

模板的 `.gitmodules` 指向作者自己的仓库，Fork 后必须改，否则本地开发会拉到别人的 gh-pages：

```bash
cd ..                      # 回到仓库根目录
rm -rf fdroid
git rm -r --cached fdroid
rm -f .gitmodules
git commit -m "移除模板的子模块指向"      # ← 必须先提交

git submodule add --force -b gh-pages https://github.com/<你>/<仓库>.git fdroid
git commit -am "fdroid 子模块指向本仓库 gh-pages"
git push origin main
```

> ⚠️ 顺序有讲究。`git submodule add` 在“`.gitmodules` 已从工作区删除、却还在 HEAD 里”时会报
> `please make sure that the .gitmodules file is in the working tree`。
> **必须先把这次删除提交掉，再 add。**

### 3.4 建 `actions` 分支

模板的 `script/init-actions.sh` 做的事：

```bash
git branch actions
git push -f origin actions
```

### 3.5 准备密钥并配置 5 个 Secrets

把签名密钥转成模板要的 PKCS12（本来就是 p12 可跳过）：

```bash
keytool -importkeystore \
  -srckeystore keystore.jks -srcstoretype JKS -srcalias fdroidrepo \
  -destkeystore keystore.p12 -deststoretype PKCS12 -destalias fdroidrepo \
  -srckeypass   '<口令>' -destkeypass   '<口令>' \
  -srcstorepass '<口令>' -deststorepass '<口令>' -noprompt

base64 -w0 keystore.p12 > keystore.p12.base64.txt
```

> PKCS12 要求 keypass == storepass。
> 口令**只用字母数字** —— 模板是把它不加引号直接写进 YAML 的，带特殊字符会把配置写坏。

然后到 `https://github.com/<你>/<仓库>/settings/secrets/actions`，加 5 个：

| Name | Secret |
|---|---|
| `KEYSTORE` | `keystore.p12.base64.txt` 的全部内容（一行，不能断行） |
| `KEYSTOREPASS` | 口令 |
| `KEYPASS` | 同一个口令 |
| `REPO_KEYALIAS` | `fdroidrepo` |
| `KEYDNAME` | `CN=... , OU=... , O=... , C=CN` |

### 3.6 启用 Actions（**最容易漏的一步**）

**Fork 来的仓库，GitHub Actions 默认是关闭的。**

打开 `https://github.com/<你>/<仓库>/actions`，顶部会有黄色横幅，点右边的：

> **`I understand my workflows, go ahead and enable them`**

不点的话，推送什么都不会发生 —— 现象是只有 `pages build and deployment` 在跑
（那是 Pages 自带的，不属于仓库 workflow）。

### 3.7 启用 GitHub Pages

`https://github.com/<你>/<仓库>/settings/pages`

- Source 选 **`Deploy from a branch`**
- Branch 选 **`gh-pages`**，文件夹 **`/ (root)`**
- Save

地址是 `https://<用户名小写>.github.io/<仓库名>/`，仓库内容在它下面的 `/repo/`。

> 仓库改名后地址会跟着变，而**索引里记录的地址是发布时写死的** ——
> 要么先定好名字再发布，要么改名后重新触发一次发布。

### 3.8 放入第一个 APK

在 `actions` 分支的 `apk/` 目录放一个 `.txt`，内容写 APK 的下载地址：

```bash
git checkout actions
git fetch origin && git reset --hard origin/actions

echo "https://github.com/<你>/<应用仓库>/releases/download/<tag>/<文件名>.apk" > apk/<名字>.txt
git add -f apk/<名字>.txt        # apk/.gitignore 是 /*，必须 -f
git commit -m "添加 <应用> 的 APK 下载链接"
git push origin actions
```

推送后去 Actions 页看 `Process APK Updates`。跑完 `gh-pages` 的 `repo/` 里会有：

```
repo/
├── com.xxx_38.apk          # APK，被重命名成 <包名>_<versionCode>.apk
├── index-v1.jar            # 索引（客户端读这个，已签名）
├── index-v2.json
├── index.xml
└── ...
```

## 4. 补应用信息（否则显示很糙）

第一次发布会用 `--create-metadata` 生成**占位元数据** —— 没有简介、没有许可证（客户端显示 Unknown）、
分类还会被错填成目录名。必须手动补。

在 `gh-pages` 分支建 `metadata/<包名>.yml`：

```yaml
Name: 应用名
Categories:
- Internet
License: AGPL-3.0-only
AuthorName: SLD-GCB
AuthorEmail: xxxx@example.com
SourceCode: https://github.com/<你>/<应用仓库>
IssueTracker: https://github.com/<你>/<应用仓库>/issues
Summary: 一句话简介（80 字以内，结尾不要句号）
Description: |
  详细描述，支持多行。
AutoUpdateMode: None
UpdateCheckMode: None
CurrentVersionCode: 2147483647
```

> `Categories` 只能用 F-Droid 的固定分类：
> Connectivity / Development / Games / Graphics / Internet / Money / Multimedia /
> Navigation / Phone & SMS / Reading / Science & Education / Security /
> Sports & Health / System / Theming / Time / Writing。

**改完元数据必须再触发一次发布**（往 `apk/` 丢个 txt），索引才会重新生成 ——
索引是发布时算出来的，不是实时读元数据。

> `fdroid update --create-metadata` **只在元数据文件不存在时**才生成占位版。
> 已写好的元数据不会被覆盖，但也**不要删** —— 删了会退回成空壳。

## 5. 日常运维

### 发新版本

见 3.8。一句话：**往 `actions` 分支的 `apk/` 丢个 txt。**

### 改应用信息

改 `gh-pages` 的 `metadata/<包名>.yml` → 推 → 再触发一次发布。

### 手动触发

Actions 页 → `Process APK Updates` → Run workflow。
或者用 `manual-push-apk.yml`，它可以在表单里直接填 APK 地址。

## 6. 备忘 / 坑

- **本地推 `actions` 之前一定要 `git fetch && git reset --hard origin/actions`。**
  因为 CI 处理完会**删掉 `apk/` 里的文件**，并把日志提交回 `actions` 分支；本地不同步就会被拒。
- 直接放 `.apk` 文件也行，但同样要 `git add -f`。
- 索引里的仓库地址是发布时写死的；改名 / 换域名后要重新触发发布。
- CI 用 fdroidserver 官方 Docker 镜像，**本机不需要 Docker**。
- 万一以后想甩掉模板、自己写 workflow，先知道这两个坑：
  - Ubuntu 24.04 自带的 `fdroidserver` 2.2.1 配的是 androguard 3.x，**解析不了 AGP 9 / compileSdk 37
    产出的 `resources.arsc`**，会报 `ResParserError: res1 must be zero!`。
    需要 androguard 4.x（它把这种情况降级成警告），且 fdroidserver 要 ≥ 2.4
    （用 `common.get_androguard_APK()` 兼容两代 androguard）。
  - `fdroidserver` **在 Windows 上跑不起来**（会卡在 Android SDK 检测），本地初始化得靠 Docker。
